# bsp_power — 板上 5V 输出使能（PC15）

文件：`bsp_power.h` / `bsp_power.cpp`

## 硬件

| 项 | 值 |
|---|---|
| 引脚 | **PC15**（CubeMX 里叫 `PC15-OSC32_OUT`，标签 **`POWER_5V`**）|
| 含义 | 板上 **5V 输出使能**（达妙 MC02 手册里的 `Power_5V_EN`，丝印 "5V EN"）|
| 有效电平 | **高电平有效**（引脚为高 = 输出 5V）|
| 本工程默认 | **关闭**（`gpio.c` 里初始化为 `GPIO_PIN_RESET`，`Robot_Init()` 里再显式 `Power_5V_Enable(false)` 一次）|

> PC15 是 **OSC32_OUT** 复用脚 —— 本工程没用 32.768kHz 晶振，所以拿来当普通 GPIO ✓
> （`tools/cubemx_post_export.ps1` 会在每次 CubeMX 导出后确认这一脚的 `.ioc` 设置没被改掉 ✓）

## API

| 接口 | 说明 |
|---|---|
| `Power_5V_Enable(bool)` | 打开/关闭板上 5V 输出 |
| `Power_5V_Is_Enabled()` | 读当前引脚电平，true = 已打开 |

## 用法

```cpp
/* Robot_Init()：出厂默认关闭(已接好) */
Power_5V_Enable(false);

/* 需要 5V 的外设(外接编码器 / 风扇 / 舵机 / 5V 传感器)在初始化时自己打开 */
Power_5V_Enable(true);
```

## 为什么默认关闭

5V 输出是**给外部负载供电**的，默认打开等于上电就给外设供电 ⇒
可能带来浪涌、外设异常动作、甚至反灌。所以本工程的原则是：
**谁需要 5V，谁在自己的初始化里显式打开** ✓

## 坑

1. 打开/关闭只是拉一根 IO ⇒ **没有过流保护**：外设电流要自己算（板上 5V 通道能力见手册）；
2. 关掉 5V 后，挂在上面的外设（编码器/传感器）**立即掉电** ⇒ 如果它的反馈还参与控制，
   记得同时把相关状态机置为"离线"，别拿着掉电后的旧数据继续算 ✗；
3. 它是**普通 GPIO**（不是电源管理芯片）⇒ `Power_5V_Is_Enabled()` 读的是**引脚电平**，
   不等于"5V 真的正常输出"（那要看外部电路）✓
