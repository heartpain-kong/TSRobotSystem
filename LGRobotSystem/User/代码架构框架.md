# 代码架构框架（LGRobotSystem）

> 这份文档回答一个问题：**新来的人怎么在这个工程里加东西，而不把结构搞乱。**
> 配套阅读：`代码风格与模板.md`（怎么写）、`App/说明.md` / `Device/说明.md` / `Bsp/说明.md` / `algorithm/说明.md`（各层细则）。

---

## 0. 这套框架是干什么的

同一套底层，支撑 **RM（RoboMaster）/ RC（ROBOCON）/ 轮椅** 等不同机器人：
**换机器人 = 只改 `User/App/` 与 `User/App/robot/robot_def.h`**，Device / Bsp / algorithm 三层基本不动 ✓

```
┌──────────────────────────────────────────────────────────────┐
│ User/App        业务:任务 + 决策 + 机器人差异(换机器人改这层)   │
│                 robot  motor_task  imu  cmd  chassis           │
│                 gimbal highRise error_task msg_center          │
├──────────────────────────────────────────────────────────────┤
│ User/Device     设备驱动:一颗芯片/一个外部设备一个模块          │
│                 dev_remote dev_referee dev_minipc dev_log      │
│                 dev_electric dev_bmi088 dev_w25q64 dev_ws2812  │
│                 dev_buzzer + motor(电机品牌类)                  │
├──────────────────────────────────────────────────────────────┤
│ User/Bsp        板级外设:把 HAL 包成"好用的接口",不含业务      │
│                 bsp_uart bsp_spi bsp_ospi bsp_adc bsp_pwm       │
│                 bsp_gpio bsp_fdcan bsp_flash bsp_power          │
│                 bsp_timestamp bsp_dwt                           │
├──────────────────────────────────────────────────────────────┤
│ User/algorithm  纯算法:只用数学,不碰硬件(可单测/可移植)        │
│                 PID Slope Kalman Mahony chassis_control         │
│                 math_support crc                                │
└──────────────────────────────────────────────────────────────┘
          ▲ 依赖只能**从上往下**：App → Device → Bsp → HAL
            algorithm 谁都能用,但它**不许反过来依赖任何人** ✓
```

**铁律（违反了很快就会乱）**
1. `algorithm` 里**不许**出现 `HAL_*`、`hspi1`、`__disable_irq` 这类东西 ✓
2. `Bsp` 里**不许**出现"底盘/云台/模式"这类业务词 ✓
3. `Device` 只认自己的芯片/协议,**不许**知道"谁是底盘" ✓
4. `App` 之间**不许**互相 include 对方头文件去读全局变量 ✗ —— 一律走 `msg_center` 的**环形数组** ✓

## 1. 启动与初始化顺序（改顺序会出玄学问题，务必照抄）

```
main.c
 ├─ HAL_Init() / SystemClock_Config() / MX_xxx_Init()   ← CubeMX 生成
 └─ USER CODE BEGIN 2
      Timestamp_Init(&htim5);   ★ 必须最先:后面所有超时/排程都用它(TIM5,1MHz,无中断)
      Robot_Init();             ← 各 BSP + 各 Device + 各 App 的 Init(只初始化,不建任务)
                                   顺序见 robot.cpp(有时间戳→通信层→电机→IMU→Flash→日志
                                   →继电器→遥控器→裁判系统→miniPC→电压→决策层)
osKernelInitialize()
MX_FREERTOS_Init()
 └─ USER CODE BEGIN RTOS_THREADS
      OSTaskInit();             ← 建所有 RTOS 任务(robot_task.cpp)
osKernelStart()
```

> ⚠️ **为什么拆成两处?** CMSIS-RTOS2 要求**先 `osKernelInitialize()` 才能 `osThreadNew()`**，
> 而 `main.c` 的 USER CODE 2 在它**之前** ⇒ 建任务只能放到 `freertos.c` 里 ✓
> （`Robot_Init()` 里**不要**建任务 ✗）

## 2. 任务清单（`User/App/robot/robot_def.h` 里改周期/优先级/栈）

| 任务 | 周期 | 优先级 | 干什么 |
|---|---|---|---|
| `motor` | 1 kHz | High | 电机初始化、CAN/485 接收分发、按各电机自己的频率发帧、逐台状态 |
| `imu` | 1 kHz | High | BMI088 读数 + 四元数 EKF → `MSG_TOPIC_IMU_*` |
| `cmd` | 500 Hz | Normal | 遥控器/键鼠 + 裁判系统 + miniPC → 统一控制指令 `MSG_TOPIC_CMD` |
| `chassis` | 500 Hz | Normal | 麦轮解算 + 里程计 + 限功率 → `MSG_TOPIC_CHASSIS` |
| `gimbal` | 500 Hz | Normal | yaw/pitch 关节角 MIT 控制 + 小陀螺前馈 → `MSG_TOPIC_GIMBAL` |
| `highRise` | 500 Hz | Normal | 末端机构(摩擦轮+拨弹 / 预留升降)→ `MSG_TOPIC_HIGHRISE` |
| `robot` | 500 Hz | Normal | 子系统服务(日志落盘/电压)+ **决策层门控** → `MSG_TOPIC_ROBOT` |
| `error` | 100 Hz | Low | 错误码量化(蜂鸣器+WS2812)+ 关键数据 10 Hz 落盘 |

任务的写法统一是"**跑一拍 + `osDelayUntil` 绝对时刻**"，超时用 `DWT` 量并计数（别用 `osDelay` 累积漂移 ✗）。

## 3. 任务间通信：环形数组（`User/App/msg_center/`）

```
生产者任务 ──Msg_Publish()──► 该话题的环形数组(静态,4 条 × 96B)──Msg_Latest()──► 任意多个消费者
```
* **静态、无 malloc** ✓（满了覆盖最旧 ✓，控制任务只关心最新一帧 ✓）
* 两个消费者用法：
  * **广播型**（一个话题多个消费者）：各自记 `seq` + `Msg_Is_New()` + `Msg_Latest()` ✓
  * **独占型**（只该被消费一次）：`Msg_Pop()` ✓
  > ⚠️ 广播型**绝不能**用 `Msg_Pop` ✗（会把数据从环形里拿走，别的任务就没了 ✓）

```cpp
/* 消费者标准写法 */
static uint32_t my_seq = 0;
Cmd_Data_t cmd;
if (Msg_Is_New(MSG_TOPIC_CMD, my_seq) &&
    Msg_Latest(MSG_TOPIC_CMD, &cmd, (uint16_t)sizeof(cmd), &my_seq))
{
    /* 用 cmd */
}
```
* 每个发大结构体的话题都要**加一句尺寸断言** ✓（否则超长会被静默拒收 ✗）：
  ```cpp
  static_assert(sizeof(My_Data_t) <= MSG_SLOT_SIZE, "My_Data_t 超过 MSG_SLOT_SIZE");
  ```
* 话题表在 `msg_center.h` 的 `Enum_Msg_Topic` ✓ —— **加话题要同时改**：枚举 + `msg_center.cpp` 的名字表 + `msg_center.md` 的表格 ✓

## 4. 一个模块长什么样（三件套）

```
User/<层>/<模块>/
├── <前缀>_<模块>.h      ← 接口(头文件保护宏 + extern "C" 包声明)
├── <前缀>_<模块>.cpp    ← 实现
└── <前缀>_<模块>.md     ← 说明(设计理由/API/坑/上板自检)★ 代码里只留简短注释
```
前缀：`Bsp` 用 `bsp_`、`Device` 用 `dev_`（**电机除外**，电机类沿用 `motor_xxx`）、`App` 用任务名（如 `chassis_task`）。

**对 C 侧暴露的头必须用 `extern "C"`** ✓（`main.c`/`freertos.c` 是 C ✓，解析不了 C++ 类 ✗）
```c
#ifndef XXX_H
#define XXX_H
#include <stdbool.h>
#include <stdint.h>
#ifdef __cplusplus
extern "C" {
#endif
/* ...声明... */
#ifdef __cplusplus
}
#endif
#endif // XXX_H
```

## 5. ★ 怎么加东西（照着做就行）

### 5.1 加一个 **Bsp 外设模块**
1. `User/Bsp/<名>/bsp_<名>.{h,cpp,md}`（从 `User/模板/` 复制 ✓）
2. 只包 HAL，不写业务；提供 `Init()` + 读/写接口
3. `CMakeLists.txt` + `CMakeLists_template.txt` 的 include 列表加目录 ✓
4. `tools/cubemx_post_export.ps1` 的 §5 清单加一条 ✓（这样自检会看着它）
5. `Robot_Init()` 里按依赖顺序 `Init()` ✓

### 5.2 加一个 **Device 设备**
1. `User/Device/<名>/dev_<名>.{h,cpp,md}`
2. 三件事：**收**（注册 BSP 回调/中断里只搬运）、**解**（`Xxx_Task()` 里组帧/校验）、**发**（`Msg_Publish` 到自己的话题）
3. 带协议的一定写清：帧格式、CRC 范围、掉线超时、统计量（`Rx_Frames/Crc_Errors/Reject_Count`）✓
4. CMake / 脚本清单 / `Robot_Init()` / 需要的话在某个任务里调它的 `Xxx_Task()` ✓

### 5.3 加一个 **algorithm 算法**
1. `User/algorithm/<名>/alg_<名>.{h,cpp,md}`（纯数学，可 `#include "math_support.h"`）
2. 头文件里尽量 `inline`/`constexpr`；单位写清楚（SI ✓）
3. 不碰硬件、不 include App/Device/Bsp ✓

### 5.4 加一个 **App 任务**（最常见）
1. 在 `robot_def.h` 加三行：`XXX_TASK_PERIOD_MS / _PRIORITY / _STACK`
2. `User/App/<名>/<名>_task.{h,cpp,md}`（从 `User/模板/` 复制 ✓）
3. `robot_task.cpp`：`#include` + `start_xxx_task()` 任务体 + `OSTaskInit()` 里 `osThreadNew` + 句柄变量
4. `robot.cpp` 的 `Robot_Init()` 里调 `Xxx_Init()`
5. 数据进出**只走 msg_center** ✓；关键量写进 `Error_Get_Snapshot()`（10 Hz 落盘 ✓）
6. CMake / 脚本清单 ✓ → 编译 + 跑 `tools\cubemx_post_export.ps1` ✓

### 5.5 加一路 **电机**
1. `User/App/motor_task/motor_task.cpp`：注册（`Init` + CAN 回调 + 使能）✓
2. `robot_def.h` 的**电机分配宏**里给它一个下标（`0xFF` = 未分配 ✓）—— **同一路电机只能归一个任务** ✗
3. 需要写目标就用 `motor_task_set_wheel_rpm()`（轮子,rpm ✓）或 `motor_task_set_mit()`（关节侧 rad/rad·s⁻¹/N·m ✓）

### 5.6 加一个 **新机器人**（比如轮椅）
1. `User/App/wheelchair/`（已预留 ✓）里按 5.4 加任务
2. 只改 `App` 层 + `robot_def.h` ✓；Device/Bsp/algorithm 不动 ✓
3. 末端机构那种"两边不一样"的地方,收成一个宏 ✓（例：`HIGHRISE_MECH_SHOOT/LIFT` ✓）

## 6. 错误处理与日志

* **错误码**：`error_task.h` 里有完整分区表（1~4 RTOS / 5~13 设备 / 20+n 电机初始化 / 40+n 离线 / 60+n 电机报错 / 80+b 自定义位 / 120+ 自定义码）✓
  * 显式报错：`Error_Set_Flag(ERROR_FLAG_MASK(ERROR_FLAG_IMU), true);` 或 `Error_Report(code, true);`
  * 显示：**蜂鸣器声数 + WS2812 8 灯二进制**（LED0 = 类别色）✓
* **日志**：`Log_Printf()` / `Log_Record()` 只写内存环形（µs 级 ✓ 不阻塞 ✓），落盘由 `Robot_Task()` 里的 `Log_Task()` 做 ✓
  * ⚠️ 别用 `%f`（newlib-nano 没开浮点 printf ✗）→ 用 `Log_Float2Str()` ✓
  * ⚠️ `Log_Task()` 必须在**同一个任务**里调（和 `bsp_flash` 共用 W25Q64 状态机 ✓）

## 9. 常见坑（血泪版）

1. **CubeMX 是引脚/外设的唯一真源** ✓ —— 不要在代码里偷偷改 CubeMX 配好的参数 ✗（要改就去 CubeMX 改，然后重跑导出脚本 ✓）
2. **BDMA 只能访问 D3 SRAM（0x38000000）** ✗ —— 给 BDMA 用的缓冲必须放 `.RAM_D3` 段 ✓（例：`ws2812_buffer`）
3. **C 文件（`main.c`/`freertos.c`/`usbd_cdc_if.c`）只能 include `extern "C"` 的纯声明头** ✗ —— 绝不能 include 电机类/出 C++ 类的头 ✓
4. **单位**：电机接口一律**关节侧** rad / rad·s⁻¹ / N·m ✓；底盘算法一律 **rpm ✓**；换算只在 `motor_task` 里做一次 ✓
5. **中断里只搬运** ✓ —— 组帧、CRC、发布消息都放到任务里做 ✓
6. **`osThreadNew` 返回值必须检查** ✓ —— 堆不够时它只返回 NULL（静默失败 ✗），失败数看 `g_thread_create_failed` ✓
7. **一个外设（一颗 Flash、一个串口）只能有一个"主人"** ✗ —— 例：`Log_Task()` 和 `bsp_flash` 都在 `Robot_Task` 里调 ✓
