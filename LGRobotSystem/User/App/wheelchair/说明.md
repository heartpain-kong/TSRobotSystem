## 1. 为什么单独留一个目录

本框架用**同一套底层**支撑多种机器人（RM / RC(ROBOCON) / 轮椅 …）：
> **换机器人 = 只改 `User/App/` 与 `User/App/robot/robot_def.h`** ✓
> `User/Device`（设备）、`User/Bsp`（板级外设）、`User/algorithm`（算法）**基本不用动** ✓

轮椅和"麦轮底盘 + 云台"的最大区别，通常就在这几件事上 —— 全都落在 **App 层**：
| 差异点 | 建议做法 |
|---|---|
| 底盘运动学（差速/阿克曼 vs 麦轮）| 在 `User/algorithm/` 加一个 `alg_wheelchair_control`（照 `chassis_control` 的样子）✓ |
| 控制输入（摇杆 / 脑机 / 手机 / 按键）| 在 `User/Device/` 加对应设备（`dev_joystick` 之类），发布话题 ✓ |
| 安全（限速、防倾倒、急停、坐姿检测）| 在本目录的任务里做，异常用 `Error_Set_Flag/Error_Report` ✓ |
| 人机界面（灯带/蜂鸣器/屏幕）| 复用 `dev_ws2812` / `dev_buzzer` ✓ |

## 2. 怎么开始（照着做就行）

1. 读 `../../代码架构框架.md`（第 5.4 节：加一个 App 任务）与 `../../代码风格与模板.md`
2. 从 `../../模板/task_template.h.tpl` / `task_template.cpp.tpl` 复制过来，**去掉 `.tpl`**，改名为：
   ```
   wheelchair/wheelchair_task.h
   wheelchair/wheelchair_task.cpp
   wheelchair/wheelchair_task.md      ← 说明文档(必须有"上板自检"一节)
   ```
3. 在 `../robot/robot_def.h` 加三行：
   ```c
   #define WHEELCHAIR_TASK_PERIOD_MS   2u
   #define WHEELCHAIR_TASK_PRIORITY    osPriorityNormal
   #define WHEELCHAIR_TASK_STACK       2048u
   ```
4. 在 `../robot/robot_task.cpp` 里：`#include "wheelchair_task.h"` + 写 `start_wheelchair_task()` + 在 `OSTaskInit()` 里 `osThreadNew` ✓
5. 在 `../robot/robot.cpp` 的 `Robot_Init()` 里调 `Wheelchair_Init()` ✓
6. 两个 `CMakeLists*.txt` 的 include 列表加 `User/App/wheelchair` ✓
7. `tools/cubemx_post_export.ps1` 的 §5 清单加 `'User/App/wheelchair'` ✓
8. 编译 + 跑脚本自检 ✓，再按自己 `.md` 的「上板自检」过一遍 ✓

## 3. 别踩的坑

1. **不要**在 `Bsp`/`Device`/`algorithm` 里写轮椅专属逻辑 ✗（那些层要能给别人复用 ✓）
2. **不要**直接读别的 App 模块的全局变量 ✗ —— 用 `msg_center` 的话题 ✓
3. **不要**抢别人已经占用的电机下标 ✗ —— 分配宏集中在 `robot_def.h`（`0xFF` = 未分配 ✓）
4. 需要新话题：改 `msg_center.h` 的枚举 + `msg_center.cpp` 的名字表 + `msg_center.md` 的表格（三处一起改 ✓）
5. 轮椅如果有**新的安全等级**（比如必须"人在环"才允许动），在 `robot` 决策层加一条门控 ✓，不要在每个任务里各写一遍 ✗
