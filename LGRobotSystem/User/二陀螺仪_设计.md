# 第二陀螺仪（外接 IMU）接入方案

> ⚠️ **现状（2026-11）**：**每块板只有一颗 BMI088**（SPI2，PC0/PC3 双片选）。
> `IMU_CHANNEL_GIMBAL` 在单 IMU 板上只是通道 0 的镜像，不是第二颗芯片。
> 本文是"要不要再加一颗外接 IMU"的**设计稿，尚未落地** ✓。
>
> 结论先说 ✓：**走 CAN（FDCAN3）** ✓，不走 RS485 ✓。
> 本文写清"为什么"、"怎么接"、"代码放哪"、"怎么和现有 IMU 融合"。

---

## 1. 需求

现有 BMI088 在板子上 ✓（`User/Device/bmi088/` ✓），走 SPI2 ✓。
第二颗陀螺仪是**外接**的 ✓，用途三选一（或叠加）：

| 用途 | 说明 |
|---|---|
**冗余** | 主 IMU 挂了还能跑 ✓（安全第一 ✓）|
**振动解耦** | 一颗贴底盘（受电机振动 ✓），一颗贴云台/机架（干净 ✓）|
**双 IMU 融合** | 两路角速度平均 / 互补滤波，降低噪声 ✓ |

---

## 2. 为什么选 CAN，不选 RS485

| | **RS485（USART3）** | **CAN（FDCAN3）** |
|---|---|---|
当前占用 | ✗ **已被电机总线占满**（YS/M8010 协议 ✓）| ✓ **完全空闲** |
多设备 | 需要**地址/私有协议** ✗；电机帧没有地址字段 ⇒ 加一个 IMU 会**污染电机解析** ✗ | ✓ 天生多节点（CAN ID 区分 ✓）|
抗干扰 | 一般 ✓ | **强**（差分 + CRC + 自动重发 ✓）|
带宽 | 4 Mbit ✓ 够 | 1 Mbit ✓ 够（陀螺仪 100~1000 Hz × 8 B ✓）|
接线 | 要在电机总线上**并联** ✗ | ✓ **独立一对线**（CANH/CANL）|

⇒ **RS485 的唯一优点**是线已经布好 ✓，但**协议冲突**的代价太大 ✗ ⇒ **选 CAN** ✓。
（`FDCAN1/2` 已被电机用 ✓，**`FDCAN3` 空闲** ✓ ⇒ 正好给第二 IMU ✓。）

---

## 3. 硬件

| 项 | 要求 |
|---|---|
总线 | **FDCAN3**（`PD0 = FDCAN3_RX`, `PD1 = FDCAN3_TX`，需在 **CubeMX** 里配 1 Mbit ✓）|
终端电阻 | 总线两端各 **120 Ω** ✓（只有两个节点 ⇒ 两颗都要 ✓）|
供电 | 外接 IMU 的 3V3/GND **与主板共地** ✓ |
建议型号 | 任意 CAN 输出的 IMU（BMI088/ICM42688 + STM32 小板的都行 ✓），**协议要能改** ✓ |

> CubeMX 需要做的只有一件 ✓：`FDCAN3` → **1 Mbit/s** → 生成即可 ✓（现有代码里 `bsp_fdcan`/`dev_motor_*` 已有 CAN 驱动 ✓ 可直接复用 ✓）。

---

## 4. 协议（建议，8 字节经典 CAN 帧）

| CAN ID | 方向 | 内容 |
|---|---|---|
`0x180` | IMU → 主板 | 角速度 `gx, gy, gz`：各 **int16**，单位 **0.01 °/s** ✓ |
`0x181` | IMU → 主板 | 加速度 `ax, ay, az`：各 **int16**，单位 **0.001 g** ✓ |
`0x182` | IMU → 主板 | 姿态/温度（可选 ✓）：`roll, pitch` 各 int16（0.01° ✓）、`temp` int16（0.01℃ ✓）、`seq` uint8 ✓ |
`0x1FF` | 主板 → IMU | 心跳/配置（可选 ✓）|

* 100 Hz 起 ✓，稳定后可到 **500~1000 Hz** ✓（1 Mbit 完全够 ✓）
* 每帧带 **`seq`** ✓ ⇒ 上层可判断丢帧 ✓

## 5. 代码放哪（分层不变）

```
User/Device/imu_ext/
├── dev_imu_ext.h      // 对外: Imu_Ext_Data_t / Imu_Ext_Init / Imu_Ext_Task / Imu_Ext_Get
├── dev_imu_ext.cpp    // 收 FDCAN3 → 解析 0x180/0x181/0x182 → 更新数据 + 超时判定
└── dev_imu_ext.md     // 说明 / 上板自检
```

* **Device 层** ✓（和 `dev_bmi088` 同一层 ✓），**只碰 `bsp_fdcan`** ✓，不碰 HAL ✓
* 发布到**新话题** `MSG_TOPIC_IMU_EXT` ✓（`msg_center` 里加一个 ✓，10 个话题的打包方式不变 ✓）
* **App 层的消费者**：`imu_task`（融合 ✓）或 `error_task`（监控 ✓）

### 对外接口（建议）

```c
typedef struct
{
    float Gyro[3];       /* rad/s(已换算,和 Imu_Data_t 一致 ✓) */
    float Accel[3];      /* m/s2 */
    float Temp_C;
    uint32_t Rx_Count;   /* 收到多少帧 */
    uint32_t Seq;        /* 最后一帧序号(丢帧可算 ✓) */
    bool  Online;        /* 200ms 没帧 ⇒ 离线 ✓ */
} Imu_Ext_Data_t;

bool  Imu_Ext_Init(void);
void  Imu_Ext_Task(void);                    /* 放 highRise/robot 任务里 1kHz 调 ✓ */
const Imu_Ext_Data_t *Imu_Ext_Get(void);
```

## 6. 和现有 IMU 怎么融合（建议分三步走）

| 阶段 | 做法 | 风险 |
|---|---|---|
**第一步** ✓ | **只监测不融合**：把第二 IMU 的数据打包进调试遥测 ✓，看它是否稳定 ✓ | 0（不影响控制 ✓）|
**第二步** ✓ | **选一个用**：`IMU_SOURCE = BMI088 / EXT` ✓（出问题时切到备份 ✓）| 低 ✓ |
**第三步** ✓ | **真的融合**：`imu_task` 里两路角速度**平均**（或按方差加权 ✓），再喂给 EKF ✓ | 中（要先确认两路坐标系一致 ✓）|

> ⚠️ 融合前必须确认两件事 ✓：**坐标系对齐**（安装方向 ✓ / 是否要转置 ✓）和**时间同步**（CAN 到达有抖动 ✓，要做时间戳 ✓）。

## 7. 实施步骤（预估 1~2 小时，不含硬件焊接）

1. **CubeMX**：开 `FDCAN3` 1 Mbit ✓ → 重新导出 ✓ → 跑 `tools\cubemx_post_export.ps1` ✓

4. `robot_task` 里加 `Imu_Ext_Task()` ✓（放 `highRise` 或 `robot` 任务 ✓）
5. 调试遥测里加**第二 IMU 的 3 轴角速度 + Online + Rx_Count** ✓（帧会变长 ✓，上位机同步改 ✓）
6. 接上硬件 ✓ → 看遥测 ✓ → 再决定"选一个用"还是"融合" ✓

## 9. 备选：如果非要走 RS485

也能做 ✓，但必须**改电机总线协议** ✓：

* 给 USART3 的所有帧加**一个字节的节点地址** ✓（电机 0x01~0x08 ✓ / IMU 0x20 ✓）
* 或者 IMU 用**另一个 UART** ✓ —— 但 `USART2` 是 RS485 预留 ✓，可以用 ✓ **前提是引脚引出来** ✓

⇒ 除非**布线限制** ✓，否则不推荐 ✓。

## 10. ★ 实测补充：达妙 **DM-IMU-L1** 的真实 CAN 协议

> 型号已确认 ✓：**达妙 DM-IMU-L1**（BMI088 六轴 ✓）
> 官方例程：`达妙\dm-imu-master\02.例程\MC02_CAN收发例程\DM-IMU\dm_imu.c` ✓
> 它**同时支持 RS485 和 CAN** ✓ —— 选 CAN ✓（理由见第 2 节 ✓）。

### 10.1 通信模型（请求/应答 + 主动上报）

```
主板 --(命令帧)--> IMU : [0xCC, reg_id, ac, 0xDD, d0,d1,d2,d3]   发给 imu.can_id
IMU --(数据帧)--> 主板 : [0xC0/reg, ...] 7 字节有效数据          带 imu.mst_id
```

* `ac = 0x00` 写 / `0x01` 读（`CMD_WRITE` / `CMD_READ`）
* 初始化后调 **`imu_change_to_active()`** ⇒ 进**主动上报**模式 ✓，不用一直请求 ✓
* 主从 ID：`imu_init(can_id, mst_id, &hfdcan3)` ✓（两个都要和 IMU 里配的一致 ✓）

### 10.2 数据帧布局（**16 bit 压缩，不是 IEEE754** ✗）

| 数据 | 字节 | 换算 |
|---|---|---|
加速度 | `[3:2]=x` `[5:4]=y` `[7:6]=z`（u16 小端 ✓）| `uint_to_float(v, -235.2, 235.2, 16)` ⇒ **m/s²** |
角速度 | 同上 | `uint_to_float(v, -34.88, 34.88, 16)` ⇒ **°/s**（要 ×π/180 转 rad/s ✓）|
欧拉角 | `[3:2]=pitch` `[5:4]=yaw` `[7:6]=roll` ⚠️**顺序不是 XYZ** | pitch ±90 / yaw ±180 / roll ±180（°）|
四元数 | 14 bit × 4 | `uint_to_float(v, -1, 1, 14)` |

```c
/* 官方写法(照抄即可 ✓) */
float uint_to_float(int x_int, float x_min, float x_max, int bits)
{
    float span = x_max - x_min;
    float offset = x_min;
    return ((float)x_int) * span / ((float)((1 << bits) - 1)) + offset;
}
```

### 10.3 需要在 `dev_imu_ext` 里照抄的寄存器号

| `reg_id` | 用途 |
|---|---|
`REQUEST_ACCEL` / `REQUEST_GYRO` / `REQUEST_EULER` / `REQUEST_QUAT` | 请求一次数据（request 模式用 ✓）|
`CHANGE_COM` | 切换通信口（485 / CAN ✓）|
`SET_CAN_ID` / `SET_MST_ID` | 设置 IMU 自己的 ID / 主机 ID ✓ |
`SET_BAUD` | 波特率（含 `CAN_BAUD_1M` ✓）|
`SAVE_PARAMETERS` / `RESTORE_SETTINGS` | 保存/恢复 ✓ |
`ACCEL_CALIBRATION` / `GYRO_CALIBRATION` | 校准 ✓ |

### 10.4 由此确定的做法

1. **CubeMX 开 `FDCAN3` @ 1 Mbit** ✓（唯一要你改的地方 ✓）
2. `dev_imu_ext` 里直接**照抄** `dm_imu.c` 的 `float_to_uint` / `uint_to_float` / 帧解析 ✓
3. 初始化序列：`imu_init(can_id, mst_id, &hfdcan3)` → 设 1 M ✓ → `imu_change_to_active()` ✓
4. 收到数据后：**陀螺 °/s × π/180 ⇒ rad/s** ✓、加速度直接用 ✓，再进 `MSG_TOPIC_IMU_EXT` ✓
5. 先只进遥测做对比 ✓（第 6 节第一步 ✓），确认坐标系一致后再谈融合 ✓

> ⚠️ 注意它和板载 BMI088 的**坐标系/方向**很可能不同 ✓ ⇒ 第一次接上后先**静止对比三轴符号** ✓，
> 再决定要不要在 `dev_imu_ext` 里做符号/轴交换 ✓。
