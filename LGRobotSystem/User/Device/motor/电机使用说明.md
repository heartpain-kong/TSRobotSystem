z# 电机模块使用说明

一个基类 `motor_mit` + 四个品牌类（大疆 / 达妙 / 宇树 / 灵足）。四个品牌**共用**同一套
控制模式枚举、状态枚举、单位（关节侧 rad、rad·s⁻¹、N·m）和频率调度接口。

| 品牌 | 类 | 总线 | 一帧几台 | 闭环在哪 |
|---|---|---|---|---|
| 大疆 | `Class_Motor_DJ` + `Class_Motor_DJ_Group` | FDCAN | **4 台共用一帧**（广播帧） | **主机**（电调只吃电流） |
| 达妙 | `Class_Motor_DM` | FDCAN | 1 台一帧 | **电机内部 PD**（MIT 帧带 Kp/Kd） |
| 宇树 | `Class_Motor_YS` | UART(485) | 1 台一帧 | **电机内部 PD**（8010 / 6014 两代协议） |
| 灵足 | `Class_Motor_LZ` | FDCAN | 1 台一帧 | 二选一：内部 PD（给 Kp/Kd）或主机（只给 T） |

---

## 1. 初始化

每个品牌的 `Init` 都能一次把 **型号 + 控制模式 + 发送频率** 定好：

```cpp
/* ---- 大疆:一组 4 台(一拖四) ---- */
static Class_Motor_DJ_Group chassis;                     // ⚠️ ≈1.5 KB,别建在栈上
const uint16_t ids[MOTOR_DJ_UNIT_MAX] = {CAN_M1_ID, CAN_M2_ID, CAN_M3_ID, CAN_M4_ID};

chassis.Init(&hfdcan1, ids, MOTOR_DJ_M3508, motor_speed, Motor_Control_Freq_1000HZ);
for (uint8_t i = 0; i < 4; i++)                          // 每台自己的 PID 参数
    chassis[i].PID_speed.Init(5.0f, 1.0f, 0.0f, 0.0f, 16384.0f, 1000.0f);

/* 大疆单台(单台一组时用) */
static Class_Motor_DJ loader;
loader.Init(&hfdcan1, CAN_M5_ID, MOTOR_DJ_M2006, motor_pos, Motor_Control_Freq_500HZ);

/* ---- 达妙 ---- */
static Class_Motor_DM dm;
dm.Init(&hfdcan1, 1, MOTOR_DM_J4310, motor_pos, Motor_Control_Freq_500HZ);

/* ---- 宇树(485) ---- */
static Class_Motor_YS ys;
ys.Init(&huart2, 0, MOTOR_YS_M8010, motor_pos, Motor_Control_Freq_200HZ);
// 6014 还可以关掉 1s 超时保护(第 6 个参数)
ys.Init(&huart2, 1, MOTOR_YS_IM6014, motor_pos, Motor_Control_Freq_200HZ, false);

/* ---- 灵足 ---- */
static Class_Motor_LZ lz;
lz.Init(&hfdcan1, 0x02, MOTOR_LZ_01, motor_pos, Motor_Control_Freq_500HZ);
```

**频率**：枚举只有 4 档，**枚举值就是 Hz**：`Motor_Control_Freq_100HZ / 200HZ / 500HZ / 1000HZ`。
`Init` 内部调用 `Set_Control_Freq()`，它会 ① 算出 `Control_Period_Us = 1000000 / 频率`；
② 把上次发送时刻回拨一个周期 ⇒ **首帧立即到期**（不用白等一个周期）。
运行中要改：`m.Set_Control_Freq(Motor_Control_Freq_100HZ);`

**控制模式**（`motor_Control_mode`，四品牌通用）：`motor_pos` / `motor_speed` / `motor_T`。
**控制状态**（`Enum_Motor_Status`）：`Motor_Status_DISABLE` / `Motor_Status_ENABLE`。

## 2. 接收：把 BSP 收到的帧丢给电机

### CAN（每条总线注册一个回调，回调里按 id 分发）

```cpp
void CAN1_Callback(FDCAN_RxHeaderTypeDef Header, uint8_t *Buffer)
{
    const uint32_t id = Header.Identifier;

    // 大疆:反馈 id 是每台单独的(0x201~0x20B),按 id 找到是哪一台
    for (uint8_t i = 0; i < chassis.Get_Unit_Count(); i++)
    {
        if (chassis[i].Get_CAN_Id() == id) { chassis[i].recv(id, Buffer, 8u); break; }
    }

    // 达妙 / 灵足:它们自己会校验 id,直接丢过去
    for (auto &m : dm_list) m.recv(id, Buffer, 8u);
    for (auto &m : lz_list) m.recv(id, Buffer, 8u);
}

bsp_can_init(&hfdcan1, CAN1_Callback);     // 每条 CAN 注册一次
bsp_can_init(&hfdcan3, CAN3_Callback);
```

### 485 / UART（一路一个电机，帧长由型号决定）

```cpp
void USART2_Callback(UART_HandleTypeDef *huart, uint8_t *buf, uint16_t size)
{
    ys.recv(0u, buf, (uint8_t)size);       // 485 没有 id,传 0(YS 的 recv 不校验 id)
}

// 注册时告诉驱动这一帧多长:8010 = 16 B,6014 = 26 B
USART_RX485_init_Ex(&huart2, ys.Get_Recv_Len(), USART2_Callback);
```

> 宇树的 `recv()` 内部会**先把整帧 memcpy 出来再解析**（BSP 的 DMA 双缓冲会在回调返回前翻面），
> 所以解析过程中缓冲区被下一帧覆盖不会出问题。

## 3. 控制任务（1 kHz）

**分工：状态（上次发送时刻、频率）放在电机里，判断放在 App 里。**
`Is_Send_Due()` **只读**，`send()` 内部才 `Mark_Sent()` 记时刻 —— 所以"先判断再发"是安全的，
不会出现"判过一次就把下次到期时刻推走、结果一帧都发不出去"的坑。

```cpp
void Motor_Task(void *argument)
{
    for (;;)
    {
        /* ① 大疆:整组一起算 → 到点一帧发出去(4 台在同一帧里) */
        chassis.PID_Calculate_All();                 // 内含各台的 can_send_Data()
        if (chassis.Is_Send_Due()) chassis.Send();   // ★ 只发一帧

        /* ② 达妙 / 宇树:自带 PD,主机只设目标 + 按频率发 */
        for (auto &m : dm_list) { if (m.Is_Send_Due()) m.send(); }
        if (ys.Is_Send_Due()) ys.send();

        /* ③ 灵足:两种用法二选一
         *   (a) 电机内部 PD:lz.Set_Pos(p); lz.Set_Kp(kp); lz.Set_Kd(kd); lz.send();
         *   (b) 主机闭环   :lz.Set_T(自己算出的力矩);          lz.send();
         */

        osDelay(1);
    }
}
```

单台大疆（单台一组）也可以自己按频率发：

```cpp
loader.Calculate();
if (loader.Is_Send_Due()) loader.send();
```

## 4. 用 PD 控制（两种落点）

### (a) 主机侧 PD —— 大疆，或"灵足只给 T"时

```cpp
chassis[0].PID_Angle.Init_PD(20.0f, 1.5f, 10000.0f);                    // 位置环 PD
chassis[0].PID_speed.Init(5.0f, 1.0f, 0.0f, 0.0f, 16384.0f, 1000.0f);   // 速度环 PI
```

`Init_PD(kp, kd, max_out, d_alpha = 0.2f)` = `Ki=0` + 自动打开

* **微分先行**（`PID_Improve_Derivative_On_Measurement`）：只对反馈微分，目标阶跃不再踢出 D 尖峰；
* **D 项一阶低通**（`PID_Improve_Derivative_Filter`，系数 `d_alpha`）。

想手动配：

```cpp
p.Set_Improve((Enum_PID_Improve)(PID_Improve_Derivative_On_Measurement | PID_Improve_Derivative_Filter));
p.Set_D_Filter_Alpha(0.15f);
p.Add_Improve(PID_Improve_Anti_Windup);          // 有积分时建议再加这个
```

**优化环节总表**（位掩码，默认 `PID_Improve_NONE` = 不带任何额外环节）：

| 位 | 作用 | 相关设置 |
|---|---|---|
| `Derivative_On_Measurement` | 微分先行（只对反馈微分） | — |
| `Derivative_Filter` | D 项一阶低通 | `Set_D_Filter_Alpha()` |
| `Output_Filter` | 输出一阶低通 | `Set_Out_Filter_Alpha()` |
| `DeadBand` | \|e\| < 死区按 0 处理（消静差抖动） | `Set_DeadBand()` |
| `Integral_Separation` | \|e\| 大于阈值时本拍不积分 | `Set_Integral_Separation()` |
| `Changing_Integration_Rate` | 误差越大积分越慢，很大就不积 | `Set_Changing_Integration_Rate(A,B)` |
| `Trapezoid_Integral` | 用 `(e+e_last)/2` 代替 `e` | — |
| `Anti_Windup` | 输出饱和时冻结积分（防"冲出去回不来"） | — |

**一个 PID 类覆盖三种用法**：位置环 `Ki=0` → PD；速度环 `Kd=0` → PI；两个都非零 → PID。
位置环的 `max_out` 是"输出的速度指令"上限，速度环的是"电流刻度"上限。
各项能单独读出来调参：`Get_Pout/Get_Iout/Get_Dout/Get_Fout/Get_Error()/Is_Saturated()`。
前馈两个口子：`KF * Target`（设定值前馈，`Init` 第 4 个参数）和
`Set_Feedforward(v)`（每拍注入，做重力/摩擦补偿用）。
`max_out`/`max_iout` **<= 0 表示不限制**；要正负不对称用 `Set_Out_Limit(min, max)`。

实测（宿主跑真代码）：

| 场景 | 关掉优化环节 | 打开对应环节 |
|---|---|---|
| 目标 0→1 阶跃（D 尖峰） | 第 0 拍输出 **1.5** | 第 0 拍 **1.0**（微分先行） |
| 反馈 ±0.02 抖动 | 输出峰峰值 0.0800 | **0.0456**（D 滤波） |
| 反馈 ±0.05 抖动 | 输出 ±5.00 | **0.00**（死区 0.1） |
| 大阶跃（\|e\|=100，阈值 5） | 首拍就积分 100 | 首拍 **0**（积分分离） |
| 闭环超调（Kp .1 / Ki .02 / out 限 5） | **+75.2** | **+16.2**（抗积分饱和，↓78%） |
| 误差阶跃 10 的首拍积分 | 10.0 | 5.0（梯形积分） |


### (b) 电机内部 PD —— 达妙 / 宇树 / 灵足（MIT 帧）

主机**一个 PID 都不跑**，只把 `(p_des, ω_des, τ_ff, Kp, Kd)` 发下去，电机固件内部算
`τ = τ_ff + Kp(p_des − p) + Kd(ω_des − ω)`：

```cpp
dm.Set_Pos(1.0f); dm.Set_W(0.0f); dm.Set_T(0.0f);
dm.Set_Kp(30.0f); dm.Set_Kd(1.0f);
dm.send();
```

同一帧靠参数退化就能得到四种语义：

| 想要 | 怎么设 |
|---|---|
| 位置 PD | `Set_Pos(p); Set_Kp(kp); Set_Kd(kd);` |
| 速度阻尼环 | `Set_Kp(0); Set_Kd(kd); Set_W(v);` |
| 纯力矩 | `Set_Kp(0); Set_Kd(0); Set_T(t);` |
| 全透传 | `Set_Pos/Set_W/Set_T/Set_Kp/Set_Kd` 都自己给 |

## 5. 使能 / 失能 / 置零

```cpp
m.enable();     // 允许发帧(命令位 = ENABLE)
m.lose();       // 停止输出(命令位 = DISABLE)
m.zero();       // 把当前位置记为机械零点
```

* **命令位 `Send_Status_Cmd`**：`enable()/lose()` 改它，**`send()` 的闸门就是它**（四品牌一致）。
  > ⚠️ **大疆例外**：它没有失能帧，`lose()` 后不能停发（电调会保持上一拍电流）⇒
  > `send()` 在 DISABLE 时**仍然继续发**，只是强制 `out=0`；见 `motor_DJ.md`。
* **实际状态 `Motor_Status`**：由反馈回读（宇树看反馈 STATUS、灵足看 pattern）；
  达妙/大疆协议里没有模式回读，只能镜像命令值。`Get_Motor_Status()` 读的是它。
* 为什么闸门不挂 `Motor_Status`：反馈丢帧/CRC 不过会白丢一拍；更糟的是电机报**故障码**
  （如达妙 `ERR=8~E`）时 `Motor_Status` 一直是 DISABLE，而某些故障恰恰要靠继续收帧才恢复。

### 5.1 ★ 发送前自检：没使能、又没故障 ⇒ 自动补一次使能（四品牌统一）

只靠初始化时 `enable()` 一次是不够的：**看门狗掉线后电机自己就失能了**
（达妙 `ERR=0xD`、灵足回到复位/标定、宇树 STATUS 掉出 FOC），掉了就永远回不来。
所以每个品牌的 `send()` 里都做同样三步（**顺序很重要**）：

```cpp
if (Send_Status_Cmd != Motor_Status_ENABLE) return;   // ① 命令位:尊重急停,绝不自愈回来
if (!Is_Enabled()) {                                  // ② 反馈说"实际没使能"
    if (Has_Fault()) return;                          //    有真故障 ⇒ 不硬使能,也不发
    enable();                                         //    无故障  ⇒ 补一次使能帧
}
... 正常发这一拍的控制量 ...
```

| 品牌 | `Is_Enabled()`（反馈说已使能）| `Has_Fault()`（需要人工处理的真故障）| 自愈动作 |
| --- | --- | --- | --- |
| 达妙 | `ERR == 1` | `ERR` ∈ `0x8~0xE` 且 **非 `0xD`**（掉线算可自愈）| 补 `0xFC` 使能帧 |
| 灵足 | 反馈 `pattern == 2`（运行）| 故障码（id bits21-16）`!= 0` | 补 `0x03` 使能帧 |
| 宇树 | 反馈 `STATUS == FOC` | `MError != 0` | 补一帧 `STATUS=FOC` |
| 大疆 | **恒 true** | **恒 false** | **无** —— 它没有使能命令帧，反馈里也没有状态/故障字段 |

> ⚠️ **①必须在前**：`lose()`（急停 / 手动失能）会把命令位置 DISABLE ⇒ 那之后既不补使能、
> 也不发控制帧 —— **急停后绝不会被"自愈"回使能状态**。

> 两个判定接口声明在基类 `motor_mit`，**默认值故意取"已使能 + 无故障"**：
> 没实现该语义的品牌（大疆）⇒ 这段自愈代码永不生效，不会凭默认值瞎发使能帧。
> 加新品牌时按上表在自己的 `send()`/`can_send()` 里抄这三步并在头文件 override 两个判定。

**大疆特别说明（安全）**：大疆没有失能指令帧，`lose()` = 该台槽位写 0 + 立刻补发一帧。

> ⚠️ **绝不能用"停止调用 `send()`"来停机** —— 电调收不到新指令会**保持上一次的电流**。
> 正确流程是 `lose()` 之后**继续发**（槽位会被写成 0）。整组停：

```cpp
chassis.Lose();     // 组内每台写 0,然后只发一帧(不是 4 帧)
```

## 6. 坑（踩过的都记在这）

1. **大疆一拖四**：同组 4 台共用一帧。用 `Class_Motor_DJ_Group`（`Send()` 内部只发一帧）；
   或 App 自己保证"一帧只发一次"。逐台调 `obj.send()` 会把同组其它台的槽位写成 0。
2. **大疆 CAN id 冲突**：GM6020 的 `0x204+id` 与 M3508/M2006 的 `0x200+id` 在 **id 5~8 撞车**，
   注册时要检查（**目前还没做**）。
3. **GM6020 电流帧 id 是 `0x1FF/0x2FF` 还是 `0x1FE/0x2FE` 待实测**：两个开源框架给出相反答案，
   我们现在按 `0x1FF/0x2FF`（和 `basic_framework` 一致），落地前用实物确认一次。
4. **485 是半双工"一问一答"**：同一时刻别连发多帧；`Is_Send_Due()` 的频率不要超过 App 对
   这一路的轮询节拍（8010 一帧 17B 发 + 16B 收，200~500 Hz 是合理范围）。
5. **达妙**：掉线(`ERR=0xD`)或报故障(`0x8~0xE`)后，故障源消失电机也**不会自恢复** ——
   驱动里已提供 `Clear_Error()`（发 `0xFF..0xFB` 清错帧），App 里判到故障就 `Clear_Error()` + `enable()`；
   `send()` 还会**发送前自检使能**：命令位是 ENABLE 但反馈 `ERR!=1` 且无真故障时自动补 `0xFC`（看门狗掉线能自愈），
   有真故障则不使能也不发；**急停(`lose()`)过之后不会自动使能回来**；
   `tx_id > 0x0F` 会让反馈里的错误位解析不可预测，注册时要拒绝。
6. **`LimitMax` 必须传引用**（已修）：按值传递会让所有 PID 的**积分限幅和输出限幅完全失效**。
7. **单位统一在关节侧（输出端）**：rad / rad·s⁻¹ / N·m。转子侧换算在各品牌内部完成
   （如大疆 `out = T / CURRENT_TO_TORQUE / Gearbox_Rate * CURRENT_TO_OUT`）。
8. **别把电机对象/组对象建在栈上**：`Class_PID` = 136 B、`Class_Motor_DJ` = 388 B、
   `Class_Motor_DJ_Group` = **1564 B**、`Class_Motor_YS` = 164 B。

### 收到的帧统一怎么转成物理量

`recv()` 内部完成：包头校验 → CRC 校验 → 定点反量化 → 转子→关节侧换算 →
写进基类的 `recv_data`（`Now_Pos/Now_W/Now_T/Temperature/MError/mode`）。
App 只需读 `Get_Now_*()`，不需要自己解析任何协议。

## 8. 上电 / 下电（启停顺序）

```cpp
/* ---- 上电 ---- */
Motor_Init();                       // ① 所有对象 Init(型号/模式/频率) + 注册接收回调
osDelay(10);                        // ② 等电机上电自检(达妙/宇树要几百 ms 才回第一帧)

chassis.Enable();  loader.Enable();                 // ③ 大疆:置命令位(不额外发帧)
gimbal_yaw.enable(); gimbal_pitch.enable();          //    达妙:发使能帧(FF..FC)
arm_j1.enable();    arm_j2.enable();                //    宇树:发一帧 STATUS=1(FOC 闭环)
// 灵足:lz.enable() 置命令位;模式/标定等参数操作再按需 read_param/set_run_mode

/* ---- 下电 / 急停 ---- */
chassis.Lose();                     // 大疆:每台槽位写 0,只发一帧
gimbal_yaw.lose();                  // 达妙:发失能帧(FF..FD)
arm_j1.lose();                      // 宇树:发一帧 STATUS=0(锁定)
```

> ⚠️ 大疆**不能靠"停止调用 `send()`"停机**（电调保持上一次电流）；`Lose()` 之后
> 控制任务**要继续跑、继续发**，只是槽位里的值是 0。

## 9. 出问题先看这几个

| 现象 | 先查 |
|---|---|
| 电机完全不动 | ① `Get_Send_Status()` 是不是 DISABLE（`lose()` 过没 `enable()` 回来）② `Is_Send_Due()` 到点没（频率设了没）③ 大疆：反馈 id/组号对不对、`OUT_MAX` 对不对、`PID` 的 `max_out` 是不是 0 |
| 电机抖 / 啸叫 | PD 的 D 项太猛：先确认**微分滤波开着**，再把 `Set_D_Filter_Alpha()` 调小（0.1→0.05）或 Kd 调小；速度环的 Ki 太大也会低频摆 |
| 有反馈但没动作 | 大疆看 `Get_Now_W()` 变不变（反馈通）；MIT 类看 `Get_Kp()/Get_Kd()` 是不是 0（0 = 纯力矩，位不动） |
| 一帧四台不同步 / 有的台不动 | 别逐台 `send()`；用组 `Send()`；或某台 `lose()` 了（槽位写 0） |
| 485 收不到 | 波特率（4 Mbps）、`USART_RX485_init_Ex` 的帧长是不是 `Get_Recv_Len()`（8010=16 / 6014=26）、半双工有没有抢跑 |
| 反馈 CRC 错计数一直涨 | 宇树看 `Get_Recv_Crc_Error_Count()`；坏帧会被丢弃、不影响控制，但一直涨说明线太长/干扰/波特率不对 |
| 达妙报错不动 | 读 `Get_MError()`：`0x8~0xE` 是故障（过压/欠压/过流/过温/丢通信/过载）；`0xD` 掉线要**重使能 + 清错** |

**中断里不要做的事**：`recv()` 只做解析，可以放 BSP 回调（ISR）里；但 `zero()`、
灵足的 `write_param()/save_param()`（内部有等待发送的 `Transmit_Wait`）**必须在任务里调**。

## 10. 时间基准（DWT 微秒时间戳）

底层用 Cortex-M7 内核自带的 **`DWT->CYCCNT`**（不占任何定时器），模块在 `User/Bsp/dwt/`：

```cpp
DWT_Init(0);                    // main.c 的 USER CODE BEGIN 2 里:传 0 = 自动取主频
uint32_t us = DWT_Get_Us32();   // 1us 步进的 32 位计数器(71.6 分钟回绕,差值比较环绕安全)
uint64_t t  = DWT_GetTimeline_us();
float    dt = DWT_GetDeltaT(&last);        // 两次调用之间的秒数
DWT_Delay_Us(5);                // ISR 里的微秒忙等(任务里别用,请 osDelay)
```

**三条时间线，各管各的**：FreeRTOS tick(SysTick,1ms) / HAL tick(TIM4,1ms) / 本模块(DWT,1us)。

三个关键点：

* **主频不能用 `SystemCoreClock`** —— H7 上它是 **HCLK = 160 MHz**，而 `CYCCNT` 走的是
  **内核时钟 D1CPRE = 640 MHz**，差 4 倍。模块内部按 `HAL_RCC_GetSysClockFreq() / D1CPRE`
  自动算；可用 `DWT_Get_CPU_Freq_MHz()` 回读核对，也可以 `DWT_Init(640)` 手动指定。
* `CYCCNT` 只有 32 位：640 MHz 下 **6.71 秒回绕一次**，回绕计数靠"每次读时间时累加"
  ⇒ **至少每 6.7 秒要读一次时间**（控制任务 1 kHz 在读，不会漏）。
* 回绕计数用**临界区（PRIMASK 存取）**保护，任务和中断都读时间戳也安全。

**上电自检（一行）**：把 `DWT_Get_Ms()` 和 `HAL_GetTick()` 同时读出来、隔 1 秒再看，
两者应基本相等；**若差 4 倍就是主频取错了**。

> 原来那套 TIM5 自由计数器（`bsp_timestamp`）已删除，`TIM5` 现在没人用 ——
> 可以在 CubeMX 里取消勾选 TIM5 把这个定时器释放出来（`MX_TIM5_Init()` 是 CubeMX 管的段）。

## 11. 引入一种新电机

分两种情况，工作量差很多。

### A. 已有品牌的**新型号**（最省事，通常半小时）

比如又买了几台达妙 J8009，或灵足 RS-04：

1. 在品牌的型号枚举里加一项（如 `enum motor_DM_Model` 加 `MOTOR_DM_J8009`）
2. 在 `Apply_Model_Limit()` 里加一个 `case`，照手册的 **SATURATE 表**填三样东西：
   * **减速比** `Gearbox_Rate`
   * **协议量程**：`Pos/W/T` 的 `max/min`（注意要填**关节侧**单位 rad / rad·s⁻¹ / N·m ——
     手册给的是转子侧或编码器刻度时，按该品牌内部已有的换算方式处理）
   * **Kp/Kd 上限**（如达妙 500 / 5，宇树 25.599，灵足 500 / 5）
3. 若它与同品牌其它型号**帧格式不同**（帧长、校验方式、包头、量化系数不同），再加一条分派 ——
   参考 `motor_YS` 用 `MOTOR_YS_M8010` / `MOTOR_YS_IM6014` 在一个类里跑两代协议的写法
4. 编译后上电自检：`Get_Now_Pos/W/T()` 是否合理、`Get_Control_Period_Us()` 是否等于 `1000000/频率`

### B. **全新品牌 / 新协议**（要新写一个类）

**① 建目录（说明单独放 .md，不写在源码开头）**

```
User/Device/motor/motor_XX/
├── motor_XX.h        类声明 + 协议常量
├── motor_XX.cpp      实现
└── motor_XX.md       ★ 文件说明写这里（源码顶部只留 // Created by ... 一行）
```

在 `CMakeLists.txt` **和** `CMakeLists_template.txt` 的 `# User include_directories BEGIN/END`
块里各加一行 `User/Device/motor/motor_XX`（两个都要加，否则 CubeMX 重新生成会把 `CMakeLists.txt`
覆盖回去），然后 Reset Cache and Reload Project（`file(GLOB)` 是配置期展开的）。

**② 继承 `motor_mit`，实现 5 个纯虚接口**

```cpp
class Class_Motor_XX : public motor_mit {
public:
    void Init(FDCAN_HandleTypeDef *hfdcan, uint16_t __id, motor_XX_Model __model,
              const motor_Control_mode &__control_mode, const Enum_Motor_Control_Freq &__freq);

    void send() override;    // 组帧 → 发送 → Mark_Sent()
    void recv(uint32_t _id, const uint8_t *_data, uint8_t _len) override;   // 解析反馈
    void zero() override;    // 置零(协议没有该指令就做软件偏置,参考 motor_YS)
    void enable() override;  // 使能
    void lose() override;    // 失能
};
```

三条必须遵守的约定（四个品牌都这么写）：

| 约定 | 说明 |
|---|---|
| **单位统一在关节侧** | 对外一律 rad / rad·s⁻¹ / N·m。转子侧刻度、减速比、定点量化系数全在类内部换算 |
| **`send()` 的闸门用命令位** | `if (Send_Status_Cmd != Motor_Status_ENABLE) return;` —— 不要用 `Motor_Status`（那是反馈回读的，可能因为故障码一直是 DISABLE）。**大疆例外**：DISABLE 时继续发 0，不 return |
| **`send()` 里做"发送前自检使能"** | 按 §5.1 的三步:闸门 → `!Is_Enabled()` 且无故障 ⇒ `enable()` → 再发。头文件里 override `Is_Enabled()` / `Has_Fault()`;没有该语义的品牌用基类默认值 |
| **频率调度交给基类** | `Init` 里调一次 `Set_Control_Freq(__freq)`；`send()` 真正发出去之后调 `Mark_Sent()`；App 只写 `if (m.Is_Send_Due()) m.send();` |

反馈一律写进基类的 `recv_data`：`Now_Pos / Now_W / Now_T / Temperature / MError / mode` ——
这样 `Get_Now_Pos()/Get_Now_W()/Get_Now_T()/Get_Motor_Temperature()/Get_MError()` 全部白拿，
App 不需要知道任何协议细节。

**③ 把收到的帧接进来**

* **CAN**：在 App 的 CAN 回调里按 `Header.Identifier` 分发 → `motor.recv(id, Buffer, 8)`
* **485 / UART**：`USART_RX485_init_Ex(huart, motor.Get_Recv_Len(), cb)` 注册帧长，回调里
  `motor.recv(0, buf, size)`
* ⚠️ **BSP 的 485 是 DMA 双缓冲 + IDLE 收帧**，回调返回前 DMA 就可能翻面覆盖缓冲区 ——
  所以 `recv()` 里**必须先把整帧 memcpy 出来再解析**（参考 `motor_YS::recv`）
* ⚠️ 回调在**中断上下文**：只做解析，别在里面阻塞（有"等待发送"的接口要留给任务调）

**④ 别漏了这些（四个品牌都有的东西）**

| 项 | 说明 |
|---|---|
| 身份接口 | `Get_CAN_Id()` / `Is_My_Feedback()` —— 接收分发要用 |
| CRC | `User/algorithm/crc/` 里已有 **CRC16-CCITT**（宇树 8010 用）和 **CRC32/MPEG-2**（宇树 6014 用）；别的多项式照现有写法加一个 |
| 定点打包夹紧 | int16 上限要压在 32767（`sat_i16()` 那种），否则浮点舍入往上偏一点就翻成 −32768、**指令极性反转** |
| 掉线守护 | 记一个"最近收到反馈的时刻"（如 `LastRxTick = HAL_GetTick()`），App 里判超时 |
| 特殊命令帧 | 使能/失能/清错/置零通常是**独立帧**，不受发送周期闸门约束（参考达妙的 0xFC/0xFD/0xFB/0xFE） |

**⑤ 接进 App**

```cpp
static Class_Motor_XX arm_j3;                       // 全局/静态,别放栈上
arm_j3.Init(&hfdcan1, 3, MOTOR_XX_M4310, motor_pos, Motor_Control_Freq_500HZ);

// 1kHz 控制任务
if (arm_j3.Is_Send_Due()) arm_j3.send();

// CAN 接收回调
if (arm_j3.Get_CAN_Id() == Header.Identifier) arm_j3.recv(Header.Identifier, Buffer, 8u);
```

**⑥ 上板前的自检清单**（逐条过，别跳）

- [ ] **往返自洽**：发 1 rad/s，`Get_Now_W()` 回读是 1 rad/s 吗？（宇树 8010 就在这里踩过
      "发送系数少了个 π、电机实际走 3.14 倍"的坑 —— 发送系数必须与反馈公式**互为逆运算**）
- [ ] 发 1 rad，回读是 1 rad 吗？
- [ ] 力矩符号：正力矩是否让关节往正方向走
- [ ] 失能：大疆（没有失能帧）= 槽位写 0 **并继续发帧**；MIT 类 = 发失能帧
- [ ] 静止时反馈 CRC 错误计数稳定为 0（`Get_Recv_Crc_Error_Count()` 之类）
- [ ] 周期：`Get_Control_Period_Us()` == `1000000 / 设定频率`；总线上帧率是否吃得消
