# User/Device 说明（设备驱动层）

> **一句话**：**一颗芯片 / 一个外部设备 = 一个模块**。负责"把这个设备用好"，不关心谁在用它。

---

## 1. 这一层管什么 / 不管什么

| 管 ✓ | 不管 ✗ |
|---|---|
| 协议解析、寄存器/帧格式、CRC | 底盘/云台等业务语义 |
| 掉线判定、在线统计、故障统计 | 控制策略、目标值从哪来 |
| 把数据发布成话题（`Msg_Publish`）| 消费话题（那是 App 的事）|
| 自己芯片的时序/超时 | 别的设备 |

**命名**：`dev_<模块>.{h,cpp,md}` ✓
**例外**：`Device/motor/` 下的电机类沿用 `motor_mit` / `motor_DM` / `motor_LZ` / `motor_YS` / `motor_DJ` ✓（历史与生态约定，别改 ✗）

| 模块 | 设备 | 关键入口 |
|---|---|---|

| `log` | **运行日志**（内存环形 → 外部 Flash 追加落盘 + 可选控制台）| `Log_Init()`、`Log_Task()`、`Log_Printf()`、`Log_Record()`、`Log_Set_Console()` |

## 3. 一个"有协议"的设备标准骨架

```
① 收（中断/回调里）：只搬运到自己的缓冲 —— 不解析、不打印、不阻塞 ✗
② 解（Xxx_Task() 里）：组帧 → 校验(长度/CRC) → 按 cmd_id 解包 → 记统计量
③ 发：数据变了才 Msg_Publish(自己的话题)  ← 不要每拍都发,会白刷环形数组 ✗
④ 状态：Online + Last_Rx_Ms + 掉线超时 + 差错计数(Rx_Frames/Crc_Errors/Reject_Count)
```
* **每个设备都要有"上板自检"**：不接设备时 `*_init_ok == true`、`Rx_Frames == 0`、`Online == false` ✓
* **掉线超时按对方帧率给**：遥控器 100 ms ✓；裁判系统 1 s（它只有 ~10 Hz）✓；miniPC 200 ms ✓

## 4. 怎么加一个设备

1. `User/Device/<名>/dev_<名>.{h,cpp,md}`（从 `User/模板/device_template.*.tpl` 复制）
2. 定好三件事：**帧格式**、**校验范围**、**掉线超时** ✓
3. 需要的话在 `msg_center.h` 加一个话题（并同步名字表与 `msg_center.md`）
4. `CMakeLists*.txt` include 列表 + `tools/cubemx_post_export.ps1` §5 清单
5. `Robot_Init()` 里 `Init()`；在某条任务里调它的 `Xxx_Task()`（通常是 `cmd` 或 `robot`）
6. 在 `error_task.h` 的错误码表里给它留一个码（初始化失败/运行异常）✓

## 5. 坑

1. **中断里只搬运** ✗ —— 组帧、CRC、`Msg_Publish` 全部放任务里 ✓
2. **一个外设只能有一个"主人"** ✗ —— 例：W25Q64 的状态机由 `bsp_flash`/`Log_Task` 共用，且**必须同一个任务**调用 ✓
3. **发大结构体前加尺寸断言** ✓（超 `MSG_SLOT_SIZE` 会被静默拒收 ✗）：
   ```cpp
   static_assert(sizeof(Xxx_Data_t) <= MSG_SLOT_SIZE, "Xxx_Data_t 超过 MSG_SLOT_SIZE");
   ```
4. **电机接口单位是关节侧** ✓（rad / rad·s⁻¹ / N·m），换算不要在设备层之外再做第二遍 ✗
5. **`%f` 打印不了** ✗（newlib-nano 没开浮点 printf）⇒ 日志里用 `Log_Float2Str()` ✓
6. **设备不认识业务** ✗ —— `dev_rc` 不该知道"拨杆上 = 小陀螺"，那是 `cmd` 的事 ✓
