## 1. 通用帧格式（裁判系统 / 上位机共用，RM 标准）

```
 0   1   SOF = 0xA5
 1   2   data_length(小端) = 4 + n     ★ 从 seq 起算到 data 末尾
 3   1   seq
 4   1   CRC8 = CRC8(字节 0~3), poly 0x31, init 0xFF
 5   2   cmd_id(小端)
 7   n   data
7+n  2   CRC16(小端) ★ 算法见 1.2,覆盖字节 5 ~ total-3
```

* `total = data_length + 5` ✓；`n = data_length - 4` ✓
* `data_length = 4` ⇒ 空数据段，整帧 **9 B** ✓；`< 4` 非法 ✗；上限 127 ⇒ 整帧最大 **136 B** ✓

### 1.2 ★★ CRC16 算法（最大的坑 ✗）

固件 `User/algorithm/crc/crc_ccitt.h` **不是标准 CCITT** ✗，而是 **Linux `lib/crc-ccitt`** 版：

| 项 | 固件实际 | 常见误解（**错** ✗）|
|---|---|---|
| 多项式 | **0x8408**（反射）| 0x1021（正序）|
| 初值 | **0** | 0xFFFF |
| 位序 | **LSB first** | MSB first |

```python
def crc_ccitt(data, crc=0x0000):
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0x8408 if (crc & 1) else (crc >> 1)
    return crc & 0xFFFF
```

> ⚠️ 用标准 CCITT 算出的值**完全不同** ✗ ⇒ 现象是“帧头找到了、长度也对，但 CRC 全错、一帧都解不出” ✗
> **0x5A 调试帧和 0xA5 协议帧用的是同一个函数** ✓ ⇒ 一处改对全都对 ✓

### 1.3 两个 CRC 的范围

| CRC | 算法 | 覆盖 | 位置 |
|---|---|---|---|
| CRC8 | poly 0x31 / init 0xFF / 不反射 | 字节 **0~3** | 字节 **4** |
| CRC16 | 见 1.2 | 字节 **5 ~ total-3** | 末尾 2 B（小端）|

### 1.4 解帧三铁律

1. 长度不够就等 ✓，够了整帧处理 ✓
2. **CRC8 失败只丢 1 字节**重新找头 ✓
3. **CRC16 失败丢整帧** ✓

## 2. 裁判系统（USART1，115200 8N1，只收）

只接 **RX(PA10)** ✓，**不要**发数据 ✗。

| cmd_id | 含义 |
|---|---|
| `0x0001` | 比赛状态（阶段/剩余时间）|
| `0x0201` | 机器人状态（血量/热量上限/底盘功率上限/三路功率输出）|
| `0x0003` | 机器人血量 |
| `0x0101` | 场地事件位图 |

`0x0201` 偏移（我们实际读的）：`2~3 Hp` · `4~5 Max_Hp` · `8~9 Heat_Limit` · `10~11 Chassis_Power_Limit` · `12/13/14` 云台/底盘/发射输出。

超时 **1000 ms** ⇒ 离线 ✓。诊断：`Crc8_Errors` 涨 = 波特率/接线 ✗；`Crc16_Errors` 也涨 = 帧长/CRC 算法 ✗（先看 1.2 ✓）。

## 3. 虚拟串口 / USB CDC

STM32 侧：

```text
CDC_Receive_HS() → MiniPC_Rx_Callback() → MiniPC_Task()
```

### 3.1 帧格式

```text
[0]      0xA5
[1]      control
           bit7..6 = 通道: 0=RC 全自动控制, 1=RM 自瞄
           bit5..0 = mode (0..63)
[2]      payload 长度 n (u8)
[3..]    payload n 字节
[n+3..]  CRC16, 小端
[n+5]    帧尾 0x5A
```

总长：

```text
total = n + 6
```

CRC16：

```text
多项式 0x8408(反射), init 0
覆盖 [0 .. n+2]  (帧头 + control + length + payload)
```

### 3.2 RC 通道（channel=0）

payload 固定 24 B：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | Mode |
| 1 | u8 | Shoot_Enable |
| 2 | u8 | Shoot_Rate |
| 3 | u8 | Reserved |
| 4~7 | f32 | Chassis_Vx |
| 8~11 | f32 | Chassis_Vy |
| 12~15 | f32 | Chassis_W |
| 16~19 | f32 | Gimbal_Yaw |
| 20~23 | f32 | Gimbal_Pitch |

长度必须严格 24 B。

### 3.3 RM 通道（channel=1）

自瞄目标通道，payload 目前预留，固件接受帧但不消费。

### 3.4 方向 / 超时

- 上位机 → STM32：上述帧
- STM32 → 上位机：`MiniPC_Send()` 裸发送，需自行组帧
- 掉线：200 ms 无有效帧
- AUTO 掉线：底盘/云台自动指令清零

## 4. 调试遥测（UART7 + USART10，921600，100 Hz）

**定长 218 字节**，`0x5A` 开头 ✓。

> ★ 解析方**必须按帧内长度字段** `[2..3]` 走 ✓ ⇒ 老固件 **186（无陀螺仪）/ 210（含陀螺仪）/ 226（加栈水位）/ **246**（再加日志上电链）都能解 ✓
> ⚠️ CRC16 同样用 1.2 的反射算法 ✓（不是标准 CCITT ✗）

```
[0]      0x5A
[1]      版本 = 1
[2..3]   帧总长 = 218(小端)
[4..5]   cmd_id = 0x0101
[6..7]   序号(+1)
[8..223] payload = 208 B
[216..217] CRC16(反射 0x8408/init 0) 覆盖 [0..215]
```

payload 偏移（从 payload 起点）：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | 错误级别（0 OK/1 WARN/2 ERROR/3 FATAL）|
| 1 | u8 | 电机台数 |
| 2~3 | u16 | 错误码 |
| 4~7 | u32 | `g_fault_code`（4 = HardFault）|
| 8~11 | u32 | `g_fault_cfsr` |
| 12~15 | u32 | `g_fault_pc`（可 `addr2line`）|
| 16~27 | 3×f32 | roll / pitch / Yaw_Total（rad）|
| 28~39 | 3×f32 | 底盘 Vx / Vy / W（m/s, m/s, rad/s）|
| 40~47 | 2×f32 | 云台关节角 yaw / pitch（rad）|
| 48~175 | 8×16 B | 电机块：`[0]`下标 `[1]`flags `[4..7]`位置(rad) `[8..11]`转速(rad/s) `[12..15]`力矩(N·m) |
| **112~115** | u32 | ★ **Flash JEDEC**（正常 0x00EF4017）|
| **116** | u8 | ★ **状态位**：bit0 flash / bit1 IMU init / bit2 IMU online / bit3 WS2812 / bit4 蜂鸣器 / bit5 日志 |
| **117** | u8 | ★ **ACC_CONF 回读**（应为 0xA8；不是 ⇒ 加速度计没配好）|
| **118~119** | u16 | ★ BMI088 错误计数 |
| **120~123** | u32 | ★ **error 任务心跳**（每拍 +1）|
| **136~151** | 8×u16 | ★ **各任务栈水位**（motor/robot/error/cmd/imu/chassis/gimbal/highRise，单位 4B）|
| **152~171** | 5×u32 | ★ **日志上电链**（boot/本次首/上次首/上次停/回绕，绝对地址）|
| **172~175** | f32 | ★ **BMI088 温度** ℃ |
| **176~207** | **8×u32** | ★★ **8 个任务的心跳**（顺序同上；**某个不涨 ⇒ 那个任务卡住** ✗）|
| **188~199** | 3×f32 | ★ **加速度 ax/ay/az（m/s²）** |
| **200~215** | 8×u16 | ★ **栈水位** motor/robot/error/cmd/imu/chassis/gimbal/highRise（单位 **4 B**，越小越危险）|
| **236~239** | f32 | ★ **BMI088 温度**（℃；走**加速度那颗 die** ⇒ 可判断加速度通路是否活着）|
| **216~235** | 5×u32 | ★ **日志上电链**：boot_id / 本次首地址 / 上次首地址 / 上次停止地址 / 回绕次数（绝对 Flash 地址，0xFFFFFFFF=无）|

工具：`E:\rm\上位机接收器\`（Windows exe / Ubuntu py）✓

### 4.1 ★ 每秒一行**可读文本**（同一端口 ×2 路）

除了二进制帧，调试口还会**每秒**发一行 ASCII 文本（1 Hz，约 60 B）。它是**给人看的**，串口助手直接就能读：

```
[LOG] boot=3 cur=0x008000 prev=0x002000 stop=0x007F00 wrap=1
```

| 字段 | 含义 |
|---|---|
| `boot` | 本次上电编号 |
| `cur` | 本次上电首地址（绝对）|
| `prev`/`stop` | 上一次上电的首/尾地址（`0xFFFFFF` = 无）|
| `wrap` | 回绕次数 |

> 上位机会把 `[LOG]` 行**单独取出来**显示在日志面板 ✓，不当成二进制垃圾 ✓；
> 想关掉：`debug_task.h` 的 `DEBUG_TEXT_ENABLE = 0` ✓

## 5. DBUS 遥控（UART5，100000 9bit 偶校验 2停止位，只收）

固定 **18 B**，约 **71 Hz**，只有 **RX(PD2)** ✓

| 字节 | 内容 |
|---|---|
| 0~5 | ch0~ch3（11 bit 打包，中位 1024）+ 拨杆 S1/S2（值 1/2/3）|
| 6~13 | 鼠标 x/y/滚轮（2 B 各）+ 左右键 |
| 14~15 | 键盘位图（`RC_KEY_*`）|
| 16~17 | **ch4**（不是 failsafe 字节 ✗）|

杆量已减 1024 ⇒ **-660 ~ +660** ✓；掉线 **100 ms** ✓；代码：`User/Bsp/rc/` + `User/Device/remote/` ✓

## 7. 上位机实现清单

1. **小端**，f32 = IEEE754 ✓
2. **CRC16 用 1.2 的反射算法** ✓✓（最容易错 ✗）
3. 按长度字段收满再解析（0xA5 用 `data_length+5`；0x5A 用 `[2..3]`）✓
4. CRC8 失败只丢 1 B；CRC16 失败丢整帧 ✓
5. f32 逐字段 `unpack_from` ✓，别 `memcpy` 结构体 ✗
6. 0x5A 是 100 Hz，300 ms 没收到判掉线 ✓
7. **不要给裁判系统发数据** ✗
8. 发指令前确认 `CMD_MODE_AUTO` ✓
