## 1. 6020 云台零点：550 counts

```c
// motor_task.cpp
#define AUX_6020_ZERO_ENC       550u   /* raw 值对应"云台指向 +Y(车头正前)" */
```

上电第一帧反馈后 `zero_to_encoder(550)`，之后 `motor_task_aux_get_pos(1u)` 就是**相对角**：

```text
pos = 0        → 云台在参考方向（550）
pos 每 1 rad   → 8192/(2π) = 1303.8 counts
```

实测（2026-11-26，静止 20 s，999 帧）：

| 时刻 | pos | counts | 说明 |
|---|---|---|---|
| 换头前 | +0.786~0.788 rad | +1025~1028 | 云台被停在 45° 位置、**闭环一直保持不动** |
| 换头后 | +0.55 rad | +718 | 同上 |

⚠️ 结论：`pos` **不是**误差，是"云台现在离参考方向多远"。`drive_yaw = 303° + pos`，
所以云台停在 45° 时，整套摇杆坐标系跟着拧 45° —— 这不是 bug，是"y+ 永远跟云台走"的设计。
要 y+ = 车头，就得让云台回到 550 那个方向（或重新标 550）。

## 2. 摇杆 → 车体系：303°

```c
#define CHASSIS_STICK_TO_BODY_YAW (303.0f * PI / 180.0f)   /* 213° + 90° */
#define CHASSIS_GIMBAL_POS_SIGN   (+1.0f)                  /* 云台与舵轮同向 */
drive_yaw = Wrap_Pi(CHASSIS_STICK_TO_BODY_YAW + CHASSIS_GIMBAL_POS_SIGN * pos);
xyv       = R(drive_yaw) · (Vx, Vy);    seat = atan2(Vy, Vx)
```

**验证方法（可复现）**：推满 x，看 `0x0104` 的 `seat0.tgt/seat1.tgt` 平均值：

```text
实测(pos=45.2°):  x 满 +  → s0=3.117 s1=2.697  平均 168.0°
                  推算式   → drive_yaw = 303+45.2 = 348.2°，优劣弧翻 180° ⇒ 168.2° ✓
```

历史教训：早期 213° 是在**云台不在零点**时标出来的，导致"y+ 偏右、90°/270° 差 90°"；
换成 303° 后 x+/y+ 才和车体对齐。

符号踩坑：`GIMBAL_POS_SIGN` 原来是 −1（`213° − pos`），表现为**"云台转 +θ，舵轮转 −θ"**。
物理上必须同向（云台转多少，舵轮就跟多少，否则推 y+ 不沿云台走）。

## 3. 舵向零位与 202 的 −10°

舵向零位由 PE2/PE3 光电找零给出（`Servo_D_Init`），`seat = dir·motor + seat_offset`，
`seat_offset = -final_angle + trim`：

```c
static const float s_d2q2_zero_bias[2]  = { 225°, 135° };  /* 上升沿 → 停位 */
static const float s_d2q2_seat_trim[2]  = { -10°, 0° };    /* 202 实测偏 10° */
```

* 先给 +10° 时**方向反了**，改 −10° 后实测 `seat0 now = 349.8°`（即 −10.2°）、
  `204` 保持 225.5°，两路都 `homing_state = 3 (DONE)` ✓
* trim 只改 `seat_offset`，**不动找零状态机**；改完不用重新找零

## 4. toe-in：两路舵轮为什么"不平行"

反解（`alg_chassis_control.cpp: count_run1`）：

```c
V_X = vx - ω·y_i;   V_Y = vy + ω·x_i;   seat = atan2(V_Y, V_X)
```

纯平移时 ω 必须为 0，两轮才平行。实测两轮差了 8.4°（满速）~24°（低速），反解出
`ω ≈ 1.35~1.5 rad/s` —— 正是航向环顶到了 `CHASSIS_HEADING_W_MAX`。

```text
Δ(toe-in) = atan(0.1625·ω / |v|)   ⇒ Δ ∝ 1/|v|，所以低速时看起来最歪
```

原因：`heading_yaw` 只在"首次锁帧 / 退出小陀螺"取一次，车被推着转过 30° 后就一直记着，
航向环于是长期顶在 1.5 rad/s。

处理（按需求：**不许认新车头**）：

```c
#define CHASSIS_HEADING_CORR_RATIO 0.03f   /* toe-in 上限 2·atan(0.707·ratio) = 2.4° */
#define CHASSIS_HEADING_I_MAX      0.2f
```

| ratio | toe-in 上限 |
|---|---|
| 0.25（改前）| ~20°（实测 ±12°）|
| 0.03（改后）| **2.4°** |
| 0.05 | 4.0° |
| 0.08 | 6.5° |

实测改后：`yaw_error ≈ −0.01 rad`、`ω ≈ 0.04~0.13 rad/s`、toe-in 2.2~4.7° ✓

操作手自己给 W（`|Chassis_W| > 0.05`）时航向环不叠加修正，松杆后仍按**原目标**转回来。

## 5. 抓数据的方法（调试助手之外）

`tools/` 里几个脚本（pyserial，921600，COM 口按实际改）：

| 脚本 | 用途 |
|---|---|
| `capture_steer_x.py` | **同时**抓上板 `Ch[2]` + 下板 seat/202/204/6020（按 payload 长度分流，天然同一时间轴）|
| `capture_steer_full.py` | 同上再加驱动 rpm、`heading_error`、实际 ω |
| `debug_uart_view.py` | 解析整帧 `0x0101` 大遥测 |
| `step_response_6020.py` / `pid_log_stats.py` | 6020 位置环阶跃 / PID 日志统计 |

⚠️ 两个坑：

1. **COM37 上跑着两块板的帧**：`payload 204 B` = 上板（有遥控、rx_count 很大、电机全 0），
   `payload 242 B` = 下板（真电机/6020，rc 恒 0）。只按 `0x0102` 收会混。
2. **下板不接遥控器**（`cmd_task.cpp`："下 MCU 不接遥控器，CAN3 指令是唯一驾驶来源"），
   所以下板帧里的 `rc.ch2` 永远是 0，摇杆必须从上板帧里取。
